## Key Architectural Points

### 1. Three-Tier Fixture Architecture
- **System-Level:** Once per test run (group 2)
- **Feature-Level:** Once per test feature (group 3)
- **Nested:** Scoped within tests via agents (group 4)

### 2. Exception-Safety Pattern
All cleanup must use rescue clauses:
```eiffel
do
    acquire_resource
    execute_work
rescue
    cleanup_resource
    raise_if_exception
end
```

### 3. DBC as Contract
Postconditions must be concrete and verifiable:
- ✓ "fixture_valid: is_valid"
- ✓ "system_initialized: is_initialized"
- ✗ "ready for testing" (too vague)

### 4. SCOOP Compatibility
All fixtures support separate actors:
- Use separate generic constraints
- Stack/registry SCOOP-safe
- No thread-local data
