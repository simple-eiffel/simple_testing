Architecture & Design

Design Principles

1. Design by Contract (DBC)

All classes use explicit contracts:

  • Preconditions (require): Caller's responsibilities
  • Postconditions (ensure): Feature's guarantees
  • Invariants: Class consistency checks

Tests verify that postconditions hold and invariants are maintained.

2. Three-Tier Fixture Architecture

Fixtures run at different scopes:

  • System-Level (TEST_SYSTEM): Once per test run (expensive setup)
  • Feature-Level (TEST_FIXTURE): Once per test feature (isolation)
  • Nested/Scoped (with_fixture): Callback-scoped (fine-grained control)

3. Mathematical Model Library (MML) Integration

All classes provide model queries for formal verification:

  • initialization_state (TEST_SYSTEM): 0 or 1
  • lifecycle_state (TEST_FIXTURE): 0 or 1

Model queries enable postcondition frame conditions to verify what did NOT change.

4. SCOOP Compatibility

All classes are SCOOP-compatible:

  • concurrency="scoop" in ECF
  • void_safety="all" enforced
  • No shared mutable state without locking
  • Separate references supported

    └── [User test classes inherit from this]

TEST_SYSTEM: System-Level Lifecycle

  • on_prepare_test_system: Initialize shared resources (once per run start)
  • on_clean_test_system: Release shared resources (once per run end)
  • is_initialized: Status query (deferred for subclasses)
  • initialization_state: Model query for MML verification

TEST_FIXTURE: Feature-Level Lifecycle

  • on_create: Create fresh state for test (once per feature)
  • on_destroy: Clean up state (once per feature)
  • is_valid: Status query (deferred for subclasses)
  • lifecycle_state: Model query for MML verification

TEST_SET_BASE_EXTENDED: Nested Fixture Support

  • on_prepare_feature/on_clean_feature: Per-feature hooks (optional)
  • with_fixture: Scoped callback execution with LIFO cleanup

TEST_SET_BASE: Assertion Methods (40+)

  • Boolean: assert, assert_true, assert_false
  • Object: assert_attached, assert_void, assert_same_reference
  • Equality: assert_equal, assert_not_equal
  • Numeric: assert_positive, assert_negative, assert_in_range, etc.
  • String: assert_string_contains, assert_string_starts_with, etc.
  • Collection: assert_count_equals, assert_iterable_empty, etc.

Contract Verification Strategy

Three-Stage Verification

Contracts are verified in three stages:

Stage 1: Precondition Satisfaction

Verify caller's responsibilities before calling feature: 

test_prepare_precondition
    local
        l_system: TEST_SYSTEM_MOCK
    do
        create l_system
        -- is_initialized is False initially
        assert ("precondition_holds", not l_system.is_initialized)
        -- Safe to call on_prepare_test_system
        l_system.on_prepare_test_system
    end
Stage 2: Postcondition Verification

Verify feature guarantees after calling: 

test_prepare_postcondition
    local
        l_system: TEST_SYSTEM_MOCK
    do
        create l_system
        l_system.on_prepare_test_system
        -- Postcondition: system_initialized
        assert ("postcondition_holds", l_system.is_initialized)
    end
Stage 3: Invariant Maintenance

Verify class invariants hold after any operation: 

test_invariant_maintained
    local
        l_system: TEST_SYSTEM_MOCK
        state: INTEGER
    do
        create l_system
        state := l_system.initialization_state
        -- Invariant: state must be 0 or 1
        assert ("invariant_before", state = 0 or state = 1)

        l_system.on_prepare_test_system
        state := l_system.initialization_state
        -- Invariant still holds
        assert ("invariant_after", state = 0 or state = 1)
    end

Frame Conditions (What Did NOT Change)

Postconditions specify state transitions with frame conditions: 

on_prepare_test_system ensures
    system_initialized: is_initialized
    state_transition: initialization_state = 1 and old initialization_state = 0
    -- Frame condition: only initialization_state changed

Tests verify frame conditions by comparing old vs. new state: 

test_frame_condition_respected
    local
        l_system: TEST_SYSTEM_MOCK
        old_state, new_state: INTEGER
    do
        create l_system
        old_state := l_system.initialization_state
        l_system.on_prepare_test_system
        new_state := l_system.initialization_state

        -- Frame condition verified
        assert ("state_changed", old_state = 0 and new_state = 1)
    end

Exception Safety Strategy

Cleanup is guaranteed even if logic throws: 

test_exception_safety
    local
        l_fixture: TEST_FIXTURE_MOCK
    do
        create l_fixture
        l_fixture.on_create

        -- Even if test logic throws, on_destroy guaranteed to run
        -- Eiffel's exception handling ensures postcondition holds
        l_fixture.on_destroy

        -- Postcondition verifies cleanup completed
        assert ("fixture_cleaned", not l_fixture.is_valid)
    end

The rescue clause in on_destroy ensures cleanup runs: 

on_destroy
    require fixture_valid: is_valid
    do
        -- Cleanup logic (may throw)
        perform_cleanup
    rescue
        -- Even if above throws, ensure postcondition holds
    ensure fixture_invalid: not is_valid
    end

Performance Characteristics

Fixture Overhead

  • System-Level: O(1) per test run (amortized)
  • Feature-Level: O(n) per n tests (one per test feature)
  • Nested/Scoped: O(1) per scope entry/exit

Assertion Overhead

  • Simple assertions: O(1) (boolean, equality)
  • String assertions: O(m) where m = string length
  • Collection assertions: O(n) where n = collection size

Memory Usage

  • Model queries: O(n) where n = collection size (for MML_MAP, MML_SET, etc.)
  • Test instances: One per test feature (garbage collected after test)

Extension Points

Adding Custom Assertions

class MY_TEST_SET
inherit
    TEST_SET_BASE
feature
    assert_positive (tag: STRING; value: INTEGER)
        do
            assert (tag, value > 0)
        end
end

Implementing Custom Fixtures

class DATABASE_FIXTURE
inherit
    TEST_FIXTURE
feature
    on_create
        do
            database.connect ("test_db")
        ensure
            fixture_valid: is_valid
        end

    on_destroy
        do
            database.close
        ensure
            fixture_invalid: not is_valid
        end

    is_valid: BOOLEAN
        do
            Result := database.is_connected
        end
end

Extending TEST_SYSTEM

class MY_APP_TEST_SYSTEM
inherit
    TEST_SYSTEM
feature
    on_prepare_test_system
        do
            -- Initialize shared resources
        end

    on_clean_test_system
        do
            -- Clean up shared resources
        end

    is_initialized: BOOLEAN
        -- Return True if system ready, False if cleaned
end
