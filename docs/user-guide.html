User Guide

Introduction

simple_testing is a production-ready test framework for Eiffel that provides:

  • Design by Contract (DBC) Support: Contracts are tests brought into classes with formal verification
  • Advanced Fixtures: System-level (once per run), feature-level (per test), and nested (scoped) fixtures
  • 40+ Assertion Methods: Comprehensive assertions for all data types
  • Mathematical Model Library (MML): Formal verification of state transitions
  • SCOOP Compatible: Concurrency-ready with proper actor model support

Installation

Add to your ECF configuration:

<library name="simple_testing" location="$SIMPLE_EIFFEL/simple_testing/simple_testing.ecf"/>

Ensure the SIMPLE_EIFFEL environment variable is set to your ecosystem root (e.g., D:\prod).

Basic Test Class

Create a test class inheriting from TEST_SET_BASE:

class MY_TEST_SET
inherit
    TEST_SET_BASE

feature -- Tests

    test_addition
        local
            l_result: INTEGER
        do
            l_result := 2 + 3
            assert_equal ("sum", 5, l_result)
        end

    test_list_operations
        local
            l_list: ARRAYED_LIST [INTEGER]
        do
            create l_list.make (5)
            l_list.extend (1)
            l_list.extend (2)
            l_list.extend (3)
            assert_count_equals ("list_size", 3, l_list)
            assert_equal ("first_item", 1, l_list.first)
        end
end

Three-Tier Fixture Architecture

1. System-Level Fixtures (Singleton)

Run once at test run start/end. Perfect for expensive setup (database, server): 

class MY_APP_TEST_SYSTEM
inherit TEST_SYSTEM
feature
    on_prepare_test_system
        do
            -- Called ONCE before any test runs
            -- Initialize database, start server, create pools
            database.connect ("test_db")
            server.start
        end

    on_clean_test_system
        do
            -- Called ONCE after all tests complete
            -- Exception-safe: runs even if tests fail
            database.close
            server.stop
        end

    is_initialized: BOOLEAN
        -- Must return True after on_prepare, False after on_clean
end

2. Feature-Level Fixtures (Per-Test)

Run before/after each test feature. Provides isolation between tests: 

test_with_isolated_fixture
    local
        l_fixture: TEST_FIXTURE_MOCK
    do
        -- Create fresh fixture for this test
        create l_fixture
        l_fixture.on_create  -- Setup

        -- Test logic - fixture in valid state
        assert ("is_valid", l_fixture.is_valid)

        l_fixture.on_destroy  -- Cleanup
        assert ("is_invalid", not l_fixture.is_valid)
    end

3. Nested/Scoped Fixtures

Execute callback in fixture context with automatic cleanup (LIFO): 

test_with_nested_fixtures
    local
        l_test: FIXTURE_HOLDER
    do
        create l_test
        l_test.with_fixture (agent do
            -- Fixture acquired here
            -- Even if exception thrown, cleanup runs
            perform_test_logic
        end)
        -- Fixture automatically released here
    end

Assertion Methods

Boolean Assertions

assert ("condition", True)
assert_true ("explicit", condition)
assert_false ("negation", not condition)

Object Assertions

assert_attached ("not_void", obj)
assert_void ("is_void", optional)
assert_same_reference ("same", obj1, obj2)
assert_not_same_reference ("different", obj1, obj2)

Equality Assertions

assert_equal ("equals", expected, actual)
assert_not_equal ("not_equals", x, y)

Numeric Assertions

assert_positive ("positive", count)
assert_negative ("negative", delta)
assert_zero ("zero", value)
assert_non_zero ("non_zero", x)
assert_in_range ("range", value, 1, 100)
assert_greater_than ("gt", value, 50)
assert_less_than ("lt", value, 50)

String Assertions

assert_string_contains ("has", output, "ERROR")
assert_string_not_contains ("no", output, "FAIL")
assert_string_starts_with ("prefix", str, "http")
assert_string_ends_with ("suffix", str, ".txt")
assert_string_empty ("empty", var)
assert_string_not_empty ("not_empty", var)
assert_string_length ("len", str, 10)

Collection Assertions

assert_count_equals ("size", 5, my_list)
assert_iterable_empty ("empty", collection)
assert_iterable_not_empty ("has_items", collection)
assert_array_has_item ("contains", arr, item)
assert_array_not_has_item ("excludes", arr, item)

Contract-Driven Testing

simple_testing is designed around Design by Contract. Contracts are tests: 

feature
    add_item (a_item: ITEM)
        require
            item_not_void: a_item /= Void
            not_duplicate: not has (a_item)
        do
            items.extend (a_item)
        ensure
            item_added: has (a_item)
            count_increased: count = old count + 1
        end

Tests verify postconditions in isolation: 

test_add_item
    local
        l_items: ITEM_LIST
        l_item: ITEM
    do
        create l_items.make
        create l_item

        l_items.add_item (l_item)

        -- Verify postconditions
        assert ("item_added", l_items.has (l_item))
    end

Mathematical Model Library (MML)

simple_testing integrates with simple_mml for formal verification. Model queries capture abstract state: 

class SIMPLE_CACHE [K, V]
feature -- Model Queries
    items_model: MML_MAP [K, V]
        do
            create Result.make_empty
            across internal_table as ic loop
                Result := Result.extended (ic.key, ic.item)
            end
        end

feature -- Tests use model queries
test_cache_correctness
    local
        l_cache: SIMPLE_CACHE [STRING, INTEGER]
    do
        create l_cache.make (10)
        l_cache.put ("key", 42)

        -- Verify using model
        assert ("has_key", l_cache.items_model.has ("key"))
        assert ("value_stored", l_cache.items_model ["key"] = 42)
    end
end

SCOOP Compatibility

simple_testing is SCOOP-ready. Use it with concurrent systems: 

test_concurrent_fixture
    local
        l_fixture: separate TEST_FIXTURE_MOCK  -- separate = separate actor
    do
        create l_fixture
        -- All calls are queued by SCOOP actor semantics
        l_fixture.on_create
        assert ("valid", l_fixture.is_valid)
        l_fixture.on_destroy
    end

Best Practices

  • Use contracts: Write require/ensure first, then tests verify them
  • One assertion per focus: Each test should verify one specific behavior
  • Name tests clearly: test_* names should describe what is tested
  • Use appropriate fixtures: System-level for expensive setup, feature-level for isolation
  • Verify postconditions: Tests check ensure clauses are satisfied
  • Check invariants: Verify class invariants hold after operations
